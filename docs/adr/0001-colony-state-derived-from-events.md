# 0001. Состояние семьи выводится из событий; ссылки на удалённые улей и матку читаем как пустые

Дата: 2026-10-11 · Статус: принято

## Контекст

У семьи (`colony`) есть денормализованные поля: `currentHiveId`, `currentQueenId`, `superCount`, `lastInspectedAt`.
Они не вводятся вручную: журнал событий — единственный источник правды, а поля **пересчитываются** из него
(`deriveColonyState`; на сервере это `events/service.ts`, на клиенте — `utils/colonyState.ts`). Повторный пересчёт даёт
тот же результат, поэтому повторная доставка событий при синке не двоит счётчики.

Улей и матку можно удалить, но удаление мягкое (`deletedAt`) и **не пишет событий**. Поэтому у семьи
`currentHiveId`/`currentQueenId` продолжают указывать на удалённую запись. Если сбросить поле локально, при следующем
pull оно вернётся: сервер выводит его из последнего события `migration`/`queen_change`.

Из-за этого раньше семья из удалённого улья пропадала с главного экрана и не предлагалась при заселении в другой улей
(условие `!currentHiveId`), а удалённая матка показывалась на странице улья.

## Решение

1. Производное состояние семьи **не чиним локально**. Пересчёт идёт только из событий, в одной транзакции с записью
   (`useEventWriter.saveEvent`), полем руками никто не владеет.
2. **Читающая сторона считает ссылку на удалённое пустой.**
    - `needsHive(colony, liveHiveIds)` (`utils/colonyRefs.ts`): активная семья без улья или с удалённым ульем нуждается
      в улье; такие семьи предлагаются в «Привязать семью» на пустом улье.
    - Запросы, читающие улей/матку по id, отбрасывают записи с `deletedAt`.
3. При удалении **занятого** улья диалог подтверждения предупреждает, что семья останется без улья.

## Последствия

- Семья без улья нигде, кроме списка «Привязать семью» на странице пустого улья, не показывается (отдельной страницы
  со списком семей в приложении нет).
- `applyColonyState` стирает поля, для которых нет событий (удаление последней миграции сбрасывает улей),
  а не оставляет устаревшее значение.

Отвергнутые варианты:

- **Обнулять `currentHiveId` локально при удалении улья** — перетирается следующим pull.
- **Писать «переезд в никуда»** — у события `migration` обязателен `toHiveId`; менять контракт ради этого не стали.
- **Запрещать удаление занятого улья** — лишнее ограничение; хватает предупреждения.
