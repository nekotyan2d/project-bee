# 0002. Синк: таблицы описания сущностей, курсор `>=`, фиксированный порядок отправки

Дата: 2026-10-11 · Статус: принято

## Контекст

Пять синкаемых сущностей: `apiary`, `hive`, `colony`, `queen`, `event`. Сервер — приёмник одного пользователя
(last-write-wins). Все id генерирует клиент (UUIDv7), поэтому отправка — идемпотентный upsert. Раньше отправка
и приём были двумя большими `switch` и пятью почти одинаковыми функциями `pullX`.

## Решение

**Отправка.** Любое изменение ставит элемент в `outbox` с ключом `таблица:id`: повторная правка той же сущности
заменяет предыдущий элемент. `flush` отправляет элементы в порядке `apiary → hive → colony → queen → event`:
улей и семья ссылаются на пасеку, матка — на семью, события — на семью, а `queen_change` — на `queenId`.
Результат ответа (`classifyStatus`): 401/403/5xx — повторить позже, прочие 4xx — отбросить, 404 при удалении — успех.

**Приём.** По одной записи на сущность, общий `pullEntity`: курсор → `GET ?since=` → в локальный вид → `bulkPut`
→ сдвиг курсора. Курсор — максимум из `updatedAt` и `deletedAt` полученных строк; сервер возвращает строки с
`>=`, поэтому граничные строки перечитываются, а `bulkPut` идемпотентен по `id`: доставка at-least-once без потерь.
Удалённая пасека уносит с собой своих детей локально (`dropApiaryChildren`), потому что сервер отдаёт только её саму.

**Таблицы описаний.** `pushers` и `pullers` в `useSync.ts` — **типизированные функции**, а не строки путей: проверка
путей, тел и ответов `openapi-fetch` остаётся на этапе компиляции. Тело `POST /events/batch` приводится приведением
типа намеренно: payload — union по типу события, а его проверяет серверный Zod.

## Последствия

- Новая сущность = таблица Dexie + запись в `pushers` + запись в `pullers` + место в `FLUSH_ORDER`.
  `pushers` — `Record<SyncTable, …>`, TypeScript не даст пропустить его запись; `pullers` и `FLUSH_ORDER` —
  массивы, их нужно обновить вручную.
- Чистые части (`classifyStatus`, `maxCursor`, сборка `outbox`) вынесены в `utils/sync.ts` и покрыты тестами;
  сам обмен с сервером тестами не покрыт и проверяется вручную.
- Отвергнутые варианты: единый `/sync` на сервере (сделано per-entity: `PUT /<сущность>/:id`, `GET /<сущность>?since=`,
  `POST /events/batch`); курсор `>` (пропускает строки одного батча с одинаковым `now()`).
