# Архитектурные решения (ADR)

Короткие записи в формате «контекст → решение → последствия». Описывают момент, когда решение принималось;
текущая структура кода описана в [../frontend-architecture.md](../frontend-architecture.md).

| №                                                  | Решение                                                                                  | Статус  |
| -------------------------------------------------- | ---------------------------------------------------------------------------------------- | ------- |
| [0001](./0001-colony-state-derived-from-events.md) | Состояние семьи выводится из событий; ссылки на удалённые улей и матку читаем как пустые | принято |
| [0002](./0002-sync-per-entity-tables.md)           | Синк: таблицы описания сущностей, курсор `>=`, фиксированный порядок отправки            | принято |
| [0003](./0003-event-types-as-typed-tables.md)      | Всё, что зависит от типа события, описывается таблицами `Record<EventType, …>`           | принято |

## Шаблон

```markdown
# NNNN. Название

Дата: ГГГГ-ММ-ДД · Статус: принято | заменено ADR NNNN | отклонено

## Контекст

Что болело и какие ограничения были.

## Решение

Что делаем.

## Последствия

Что стало проще, что сложнее, какие альтернативы отвергли и почему.
```
